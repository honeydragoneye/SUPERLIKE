# Superlike

Spotify 계정으로 음악을 듣는 서드파티 웹 플레이어입니다. 한 곡을 고르면 비슷한 곡으로
이어지는 **스테이션**을 만들고, 태그로 다음 곡 목록을 걸러 들을 수 있습니다.

## 주요 기능

- **재생**: 브라우저에서 바로 재생 (Spotify Premium 계정 필요)
- **스테이션**: 곡 하나를 기준으로 비슷한 곡 대기열을 자동 구성
- **태그 필터**: 가사 없음 / 가사 있음 / CLEAN(19금 제외) / 장르
- **검색**: 곡 · 앨범 · 아티스트 · 플레이리스트. 검색창 아래 제안은 곡 6줄이 기본이고, 친 말이 가수나 앨범 이름과 같으면(악센트·기호·대소문자 무시, 오타 한두 글자는 정확히 같은 이름이 없을 때만) 그 가수(동명이인은 가장 유명한 쪽 1명)와 앨범이 위 2줄까지 올라와 누르면 해당 페이지로 갑니다. 한 번의 요청으로 곡·가수·앨범을 함께 찾습니다
- **가사**: 하단 플레이어 바의 `가사` 버튼으로 여는 팝업. 재생 위치에 맞춰 지금 부르는 줄이 강조되고 따라갑니다(UP NEXT 팝업과 한 번에 하나만 열림)
- **음량**: 하단 바의 스피커 버튼(UP NEXT 왼쪽)을 누르면 위로 슬라이더가 열립니다. 스피커를 누르면 음소거(버튼이 파랗게), 슬라이더를 끌면 음량이고 음소거도 풀립니다. 값은 이 브라우저에 저장되어(`lib/volume.ts`) 다음에 열어도 그대로이고, 다른 팝업(UP NEXT·가사·메뉴)과 한 번에 하나만 열립니다
- **플레이리스트**: 하단 바의 `+`로 지금 듣는 곡을 내 플레이리스트에 담고, `···`로 스테이션 시작·다음에 재생·아티스트/앨범 페이지·링크 복사를 합니다
- **마이페이지**: 좋아요한 곡, 재생 횟수
- **라디오(ON AIR 바)**: 맨 위 파란 바가 라디오입니다. Spotify에 연결하면 최근 재생한 아티스트의 장르(Last.fm 태그)로 [Radio Browser](https://www.radio-browser.info/)에서 방송국 3곳을 골라 한 곳을 바에 올려 두고, 재생 버튼으로 틀 수 있습니다(장르별로 하나씩, 한국어·영어 방송국을 우대, `다른 방송국`의 `↻ 다시 추천`으로 다른 후보). 방송국의 하트로 즐겨찾기하면 `다른 방송국` 팝업의 `즐겨찾기` 탭에 모여 최근에 들은 순으로 다시 틀 수 있습니다. 즐겨찾기는 DB(`radio_favorites`)에 계정별로 저장되어 `DATABASE_URL`이 있어야 합니다. 라디오와 Spotify는 동시에 재생되지 않고 한쪽을 켜면 다른 쪽이 멈춥니다. 스트림 주소는 만료되는 서명이 붙은 곳이 있어 저장하지 않고 틀 때마다 새로 받으며(`/api/radio/stream`), HLS(.m3u8)는 hls.js로 재생합니다. https 스트림만 제공합니다(http는 브라우저가 막음). Radio Garden은 공식 API가 없고 서버 호출이 막혀 있어 쓰지 않습니다

## 준비물

- Node.js 20 이상
- [Spotify 개발자 대시보드](https://developer.spotify.com/dashboard)에서 만든 앱의 Client ID
- [Last.fm API 키](https://www.last.fm/api/account/create) (스테이션 추천과 장르 태그에 사용)

Spotify 앱의 Redirect URI에 아래 주소를 그대로 등록해야 합니다.

```
http://127.0.0.1:3000/api/spotify/callback
```

## 실행 방법

```bash
npm install
cp .env.example .env.local   # 복사한 뒤 아래 값을 채웁니다
npm run dev
```

`.env.local`에 넣을 값:

| 이름 | 설명 |
| --- | --- |
| `NEXT_PUBLIC_SPOTIFY_CLIENT_ID` | Spotify 앱의 Client ID |
| `SPOTIFY_REDIRECT_URI` | 위에 등록한 Redirect URI |
| `LASTFM_API_KEY` | Last.fm API 키 |

브라우저에서 **http://127.0.0.1:3000** 을 열고 오른쪽 위 `CONNECT`를 눌러
Spotify에 연결합니다. `localhost`가 아니라 `127.0.0.1`로 접속해야 로그인이 됩니다.

## 색

화면의 색은 **잉크 · 쿨 화이트 · 포인트 블루(`#3D5AFE`)** 세 가지입니다(`app/globals.css`의 `@theme`). 포인트(`accent`)는 재생, 선택, 눌림, 맨 위 띠에만 쓰고, 칸이나 칩은 색 대신 한 단계 진한 쿨 화이트(`soft`)로 나눕니다. 앨범 표지에서 뽑는 색(에디터스 픽, 레코드, 플레이리스트 커버)은 음원의 색이라 이 팔레트 밖입니다. 에러 표시(`alert`)만 따로 붉은색입니다. 주간 메일은 자기 색 체계(`scripts/issue.mjs`의 컨셉 4종)를 그대로 씁니다.

## 글꼴

영문과 숫자는 **Hanken Grotesk**, 한글은 **Noto Sans KR**입니다(`app/layout.tsx`, 둘 다 `next/font/google`로 내려받아 직접 호스팅). Hanken Grotesk에는 한글이 없어서, 글꼴 순서를 Hanken → Noto로 두면 한 문장 안에서도 글자마다 알맞은 쪽이 쓰입니다.

## 화면 스크롤 구조

화면은 가장자리까지 채워서(바깥 여백과 헤더 테두리 없음) 보여 줍니다. 창 높이를 고정하지 않고 **페이지 전체가 스크롤**됩니다. 티커와 헤더는 페이지와 함께 올라가고, 액션 바(검색창·PLAY ALL)는 맨 위에 붙어 따라옵니다. 가운데 화면 옆 칸(홈의 에디토리얼 칸, 스테이션의 태그, 아티스트·앨범·검색 옆 칸, 챗봇)은 화면에 붙어 있고 담은 내용이 더 길면 칸 안에서 따로 스크롤됩니다(스크롤바는 마우스를 올렸을 때만 보이고, 칸 끝에 닿아도 페이지가 따라 움직이지 않습니다). 플레이어는 창 맨 아래에 끝까지 채워 고정입니다. 붙는 칸의 높이는 창에서 위 가장자리에 닿았을 때 남는 만큼으로 고정이라 스크롤해도 안의 블록 크기가 변하지 않습니다(닿기 전에는 아래쪽이 플레이어 뒤에 가려져 있을 뿐입니다). 홈의 이 주의 아티스트 블록이 남는 높이를 채우고, 창이 너무 낮으면 칸 안에서 스크롤됩니다. 챗봇 칸만은 입력창이 칸 맨 아래라서, 보이는 만큼의 높이(창 − 칸의 위치 − 플레이어)로 맞춥니다 — 페이지 맨 위에서는 조금 짧고, 헤더가 올라가면 늘어나며 입력창은 언제나 플레이어 바로 위에 있습니다. 구현은 `components/app-shell.tsx`와 `app/globals.css`의 `.rail-scroll`입니다.

## 아티스트·앨범·검색 옆 칸

가운데 화면 오른쪽의 칸은 화면마다 다릅니다(챗봇을 열면 챗봇이 이 자리를 씁니다).

- **아티스트**: `ABOUT`(이름, Wikipedia 소개 두세 문장, 팔로워·Last.fm 청취자·장르)과 `DISCOGRAPHY`. 앨범을 발매된 순서로(최신이 위) 한 줄씩, 연도 · 점 · 표지 · 앨범명으로 세로 선에 이어 보여 주고, 앨범명을 누르면 그 앨범으로 갑니다. 처음 8개만 보이고 `더 보기`로 나머지를 펼칩니다. 같은 해에 같은 이름의 에디션은 한 줄입니다.
- **앨범**: `ABOUT THE ALBUM`(Wikipedia 소개, 발매일·레이블·수록·장르)과 같은 아티스트의 발매 연표(지금 보는 앨범은 분홍 점으로 표시되고 눌러도 이동하지 않습니다).
- **검색 결과**: `TOP RESULT`(친 말이 가수나 앨범 이름과 같을 때만, 검색 제안과 같은 이름 규칙)에서 인기곡 재생·스테이션 시작·페이지로 이동, 그리고 `RECENT SEARCHES`(이 브라우저에만 저장, 최대 8개, 개별·전체 삭제).

소개 글은 `GET /api/about/artist?name=`, `GET /api/about/album?name=&artist=`가 줍니다. Wikipedia에서 제목이 이름과 같고 음악 이야기가 있는 문서를 찾고(한글 이름은 한국어판부터), 없으면 Last.fm의 글을 쓰며, 12시간 동안 기억합니다. 로그인이 필요 없습니다. 아티스트 화면과 옆 칸은 같은 요청을 나눠 씁니다.

## 플레이리스트

Superlike 안에서 만드는 플레이리스트입니다(Spotify 계정에 만들어지지 않고, 재생만 Spotify로 합니다). 공유 DB가 있어야 쓸 수 있습니다(`playlists`, `playlist_tracks` 테이블, `npm run db:migrate`).

- **담기**: 하단 바의 `+`(또는 `···` 메뉴의 `플레이리스트에 담기`)가 어느 플레이리스트에 담을지 고르는 창을 엽니다. 이미 담긴 곳은 `✓ 담김`이고 다시 누르면 빠집니다. 창에서 새 플레이리스트를 만들면 지금 곡이 첫 곡으로 담깁니다. 담은 뒤 5초 동안 `실행 취소`가 보입니다.
- **`···` 메뉴**: 이 곡으로 스테이션 시작 · 플레이리스트에 담기 · 다음에 재생(스테이션이 돌 때는 빠집니다. 지금 곡을 한 번 더 대기열에 넣는 것이라 Spotify 대기열 API를 씁니다) · 아티스트/앨범 페이지로 이동 · 링크 복사. 스테이션이 분위기 태그로 돌 때는 `<태그> 아님`이 맨 위에 붙습니다.
- **보기**: 홈 아래의 `내 플레이리스트`(최대 50개)에서 열고, `/playlist/[id]`에서 전체 재생·곡 눌러 재생·곡 빼기·이름 바꾸기·삭제를 합니다. 같은 주소의 Spotify 플레이리스트 id와는 uuid인지로 구분합니다. 한 플레이리스트는 500곡까지입니다.
- **커버**: 가장 먼저 담긴 곡의 앨범 표지에서 색을 뽑아 Editor's Pick처럼 그립니다(배경색이 어두운 모서리로 번지고 오른쪽 위에 레코드). 서버가 Spotify 이미지 주소만 받아 색을 뽑아 `playlists.palette`에 저장하고, 첫 곡이 바뀌면 다시 뽑으며, 곡이 없으면 회색 빈 커버입니다. 색이 없던 플레이리스트는 목록을 열 때 채워집니다.
- **공개 범위**: 만들 때 고를 수 있고 저장은 하지만, 지금은 본인만 볼 수 있습니다(다른 사람에게 보여 주는 기능은 아직 없습니다).
- 모든 조회·수정·삭제는 서버가 확인한 로그인 계정으로만 걸립니다. `GET·POST /api/me/playlists`(`?track=<id>`로 그 곡이 담긴 곳 표시), `GET·PATCH·DELETE /api/me/playlists/[id]`, `POST·DELETE /api/me/playlists/[id]/tracks`.

## 챗봇 (선택)

헤더의 눈 버튼을 누르면 오른쪽에 챗봇이 열립니다. 듣고 싶은 분위기를 말하면 실제로 있는 곡만 골라 카드로
보여 주고, 카드에서 바로 재생하거나 스테이션을 시작할 수 있습니다. 챗봇과 가운데 화면 사이의 선을
끌면 폭이 바뀌고(창 너비의 절반까지), 더블클릭하면 처음 폭으로 돌아갑니다.

챗봇은 Next.js와 별개의 프로세스(`agent/`)가 답합니다. `.env.local`에 `GEMINI_API_KEY`가 있으면 Gemini를 쓰고
(대화와 곡 판정 모두), 없으면 로컬 Ollama의 Qwen을 씁니다. `AGENT_PROVIDER=ollama`로 키가 있어도 로컬 모델을
고를 수 있습니다. 쓰려면 터미널을 하나 더 열어 아래를 한 번 준비하고 실행합니다.

```bash
# 로컬 모델을 쓸 때만: ollama list 에 qwen3-8b-local 이 보여야 합니다
python3 -m venv agent/.venv
agent/.venv/bin/pip install -r agent/requirements.txt
npm run agent                                 # http://127.0.0.1:8765 에서 대기
```

**출처 고르기**: 챗봇은 먼저 Last.fm으로 찾고, 거기서 답할 수 없으면 지어내지 않고 "찾지 못했어요"라고 말한 뒤 `Wikipedia에서 찾기` · `MusicBrainz에서 찾기` 버튼을 보여 줍니다. 누르면 같은 질문을 그 출처까지 써서 다시 찾습니다. 모두 키 없이 무료입니다.

**내 취향**: `좋아요 N곡` 또는 `재생 기록 4주` 버튼을 켜면 좋아요한 곡이나 최근 4주 동안 많이 들은 곡(합쳐서 최대 30곡)이 챗봇에게 보여서 "내 취향에 맞는 곡 추천해줘"에 답합니다(이미 들었거나 좋아요한 곡은 추천에서 빠집니다). 곡 정보가 모델(Gemini)로 전달되는 것이라 둘 다 기본은 꺼져 있습니다.

**페이지 링크**: 가수·곡·앨범에 대해 물으면 설명 글 아래에 Superlike 페이지로 가는 카드가 붙습니다. 가수를 물으면 `/artist/[id]`, 곡을 물으면 그 곡 카드와 곡이 든 앨범의 `/album/[id]`, 두 가수를 견주어 달라고 하면 가수마다 카드가 붙습니다. 카드는 도구(Last.fm·MusicBrainz)가 돌려준 이름으로만 만들고, 화면이 그 이름을 Spotify에서 찾아 이름이 일치할 때만 링크를 켭니다(동명이인은 가장 유명한 쪽). 곡 카드로 이미 Spotify에서 찾은 곡의 앨범과 아티스트는 이름을 다시 검색하지 않고 그 곡이 알려 준 id로 바로 연결하고(이름 표기가 달라 못 찾는 일이 없습니다), 이름 검색이 아티스트를 못 찾았을 때도 같은 대화에서 찾은 그 가수의 곡이 있으면 그 곡의 아티스트 id를 씁니다. 찾지 못하면 "일치하는 페이지를 못 찾았어요"와 함께 버튼이 `검색에서 열기 →`로 바뀌어 그 이름(앨범은 "앨범명 가수")으로 `/search?q=`를 엽니다(막다른 길이 되지 않게), Spotify에 연결하지 않았으면 "Spotify를 연결하면 열 수 있어요"로 비활성입니다. 이름 비교는 악센트·대소문자·기호를 무시하고(JAY-Z와 JAŸ-Z), 한두 글자 오타와 한쪽이 다른 쪽을 통째로 포함하는 이름(blackskirt와 The Black Skirts)도 인정하며(짧은 이름은 정확히 같아야 합니다), 한글 이름은 에이전트가 물어본 영어 이름으로도 다시 찾습니다(검정치마와 The Black Skirts). Spotify가 맞춘 가수보다 위에 올려 둔 비슷한 이름의 다른 가수가 있으면 `혹시 이 가수를 말씀하셨나요?`로 카드를 하나 더 보여 줍니다.

**지금 듣는 곡**: "이 곡 뭐야?", "지금 나오는 노래 설명해 줘", "이거랑 비슷한 곡"처럼 지금 재생 중인 곡을 가리키는 질문에는 챗봇이 그 곡을 알고 답합니다. 화면은 질문을 보낼 때마다 재생 중인 곡(제목·가수·앨범)을 같이 에이전트에 보내지만, 모델에게는 처음부터 보여 주지 않고 모델이 `now_playing` 도구를 부를 때만 알려 줍니다(상관없는 질문은 지금 곡에 끌려가지 않고, 곡 정보가 필요할 때만 모델로 갑니다). 재생 중인 곡이 없으면 "지금 재생 중인 곡이 없어요"라고 답하고, 별도 버튼은 없습니다(질문만으로 동작). 화면이 곡 정보를 보내지 않은 경우에는 에이전트가 알 수 없다고 안내합니다.

**가수만 말했을 때**: "유재하 노래 있어?"처럼 곡 제목 없이 가수만 말하면 에이전트는 제목을 짐작하지 않고 그 가수의 대표곡(Last.fm 인기순 5곡)을 카드로 보여 줍니다. 제목을 말했는데 못 찾으면 "그 제목은 못 찾았지만 대표곡은 찾았어요"라고 알리고 같은 가수의 대표곡 카드를 대신 보여 줍니다.

**챗봇이 대신 하는 일** (Spotify에 연결한 사용자): "지금 듣는 노래 좋아요 눌러줘", "다음 곡", "일시정지", "Everlong 틀어줘", "지금 듣는 노래로 스테이션 만들어줘", "방금 추천해준 곡들로 플레이리스트 만들어줘"처럼 시키면 해 줍니다. 에이전트는 계정이 없어 아무것도 직접 하지 않고, 도구(`like_track`·`playback`·`start_station`·`make_playlist`)가 "이걸 하자"는 제안만 돌려주면 로그인한 브라우저가 앱의 좋아요 저장소·플레이어·플레이리스트 API로 실행합니다(`components/chat/chat-actions.ts`). 좋아요와 재생은 바로 실행하고 카드의 `취소`·`일시정지`로 되돌리며, 셔플·반복("셔플 켜줘", "한 곡 반복", "전체 반복", "반복 꺼줘")·재생 위치("1분 30초로", "처음부터", "30초 뒤로")·음량("볼륨 30으로", "소리 줄여줘", "음소거")도 바로 하고 **플레이어 카드**(재생 바를 작게 줄인 카드: 곡, ⇄ ⏮ ▶/❚❚ ⏭ ↻, 진행 막대)나 **음량 카드**(슬라이더)로 보여 줍니다. 이 카드들은 대화에서 가장 최근 것만 살아 있어서 버튼이 눌리고 플레이어를 따라가며, 이전 것은 한 줄 기록으로 접힙니다. "Everlong 한 곡만 틀어줘"처럼 두 가지로 읽히는 말은 바로 틀지 않고 `이 곡만 계속`(한 곡 반복)과 `한 번만 듣기`(이 곡 하나만 틀고 멈춤) 중에서 사용자가 고르는 카드를 보여 줍니다. 스테이션은 만드는 동안 진행 표시와 `취소`가 보이고, 플레이리스트는 이름과 곡을 보여 준 뒤 `만들기`를 눌러야 만들어집니다(곡은 대화에서 이미 Spotify에서 찾은 추천 카드, 스테이션의 곡, 지금 듣는 곡 중에서 화면이 고릅니다). "다음 곡", "일시정지", "좋아요"처럼 짧고 분명한 명령은 모델이 도구를 안 부르고 말만 하는 일이 있어서 코드가 먼저 알아봐 도구를 부릅니다(`agent/loop.py`의 `_direct_action`). 스테이션을 만들었다면 "스테이션에 어떤 곡 있어?", "스테이션의 Everlong은 어떤 곡이야?"처럼 물을 수 있습니다: 화면이 스테이션의 곡을 질문과 함께 보내고, 모델은 `station_info`로 목록을 본 뒤 곡마다 `track_info`·`artist_info`로 자세히 찾아 답합니다. 연결하지 않은 방문자에게는 동작 도구가 없고 "Spotify를 연결하면 할 수 있어요"라고 안내합니다. 곡 삭제나 플레이리스트에서 곡 빼기는 아직 못 합니다. 동작 카드의 결과는 저장하지 않아서, 저장한 대화를 다시 열어도 같은 동작이 되풀이되지 않습니다. "다음에 뭐 나와?"는 **UP NEXT 카드**(곡 3개와 재생 버튼, 나머지는 "외 N곡")로, "가사 보여줘"는 가사 화면을 열고, "스테이션 꺼줘"는 스테이션을 끝냅니다(지금 곡은 계속 재생). "이 곡 내 플레이리스트에 담아줘"는 **담기 카드**(내 플레이리스트 목록과 `담기`, 이미 담긴 곳은 `담았어요 ✓`, `+ 새 플레이리스트에 담기`)로 고르게 하고, 눌러야 담깁니다.

**Gemini 사용 한도**: 무료 등급은 분당·하루 한도가 있습니다. 분당 한도에 걸리면 챗봇이 서버가 알려 준 시간만큼 기다리면서 "요청이 몰려서 N초 기다리는 중…"을 보여 주고, 그래도 안 되면 몇 초 뒤에 다시 시도하라고 알립니다. 하루 한도(한국 시간 오후 4~5시쯤 새로 시작)를 다 쓴 경우에는 기다리지 않고 바로 그렇게 알립니다. 답을 못 한 질문에는 `다시 시도` 버튼이 붙습니다. 스테이션의 분위기 태그 분류도 같은 구분으로 안내하고, 하루 한도가 찬 동안은 30분마다 한 번만 다시 확인합니다.

**대화 이력**: Spotify에 연결했다면 챗봇 헤더의 시계 버튼으로 지난 대화를 다시 열 수 있습니다. 답이 끝날 때마다, 챗봇 창을 닫거나 `NEW`를 누를 때, 그리고 새로고침하거나 탭을 닫을 때(답을 기다리던 질문까지) 지금 대화가 자동으로 계정(DB `chats`)에 저장되고, 새로고침하면 그 탭에서 열려 있던 대화가 그대로 다시 열립니다(창을 닫아 둔 채 새로고침하면 닫힌 채로 있습니다). 저장은 계정(DB `chats`)에 됩니다(질문이 하나 이상 있는 대화만, "태그 다듬기" 대화는 제외, 계정마다 최근 20개). 불러온 대화를 이어서 하고 닫으면 같은 항목에 덮어씁니다. 모든 조회와 삭제는 서버가 확인한 로그인 계정으로만 걸려서 다른 사용자의 이력은 보이지 않습니다. 곡 카드는 곡명과 가수명만 저장하고 열 때 Spotify에서 다시 찾습니다. `GET·POST /api/me/chats`, `GET·DELETE /api/me/chats/[id]`.

**당신의 취향(홈)**: 홈 가운데 맨 위 블록입니다. 서버가 `plays_daily`의 최근 4주를 가수별로 합산합니다(2주마다 가중치가 절반이 되고, 하루에 같은 곡을 5번 넘게 들은 것은 5번까지만 셉니다). 재생이 5번 이상이면 맨 위에 **최근 들은 앨범**(Superlike에서 20초 이상 들은 곡의 앨범, 최근 90일, 최대 12장, 최근 순)을 커버로 보여 줍니다. 커버를 누르면 앨범 페이지로 가고, 커버 위 재생 버튼은 앨범 전곡을 틀어요. 앨범 이름과 커버는 재생할 때 같이 저장하고(`plays_daily`), 저장되기 전의 재생은 처음 열 때 Spotify에서 받아 채웁니다(`GET /api/me/albums`). 그 아래에는 상위 가수 중 두 가수와 비슷한 가수(Last.fm)의 대표곡 5곡을 보여 줍니다. 이미 들었거나 좋아요한 곡은 빼고, `새로 받기`를 누르면 다른 비슷한 가수에서 다시 고릅니다. 이 계산에는 모델(Gemini)을 쓰지 않고, Last.fm에는 가수 이름만 보냅니다. `GET /api/me/taste?round=N` (`recs=0`이면 추천 없이 많이 들은 곡만).

**내 태그 다듬기**: TAGS 패널에서 만든 내 태그를 선택하면 `대화로 다듬기` 버튼이 나옵니다(챗봇을 연 뒤
"내 태그 다듬기"에서 골라도 됩니다). 그 태그에 넣고 싶은 곡을 말하면 챗봇이 기준을 영어 한 문장으로 정리하고,
실제 곡 20개에 적용해 몇 곡이 통과하는지 미리 보여 줍니다. `적용`을 눌러야 태그의 정의가 바뀌고, 바뀐 정의는
다음 재생 목록을 만들 때부터 쓰입니다. (이름만 있는 태그는 판정기가 기준을 알 수 없어서, 기준을 말로 적어 주는 것이
예시를 모으는 것보다 훨씬 정확합니다 — `agent/experiments/personal_tag_exp.py`)

`LASTFM_API_KEY`는 위 `.env.local` 값을 그대로 씁니다. 에이전트를 켜지 않으면 챗봇 패널에 안내 문구가 나오고
나머지 기능은 그대로 동작합니다. 구조와 실험 스크립트는 [agent/README.md](./agent/README.md) 참고.

## 공유 DB (선택)

좋아요와 재생 기록은 기본적으로 브라우저에만 저장됩니다. `.env.local`에 `DATABASE_URL`(Neon 같은 Postgres)을
넣으면 로그인한 Spotify 계정별로 DB에도 저장되고, 다른 기기에서도 같은 좋아요가 보입니다. 처음 한 번 테이블을
만듭니다.

```bash
npm run db:migrate        # lib/db/schema.sql 적용 (여러 번 실행해도 안전)
```

`OWNER_SPOTIFY_ID`(용눈이 계정의 Spotify 사용자 ID, 로그인한 채로 `/api/spotify/me`에서 확인)를 넣으면 홈의
**Editor's Pick**이 그 계정이 가장 최근에 좋아요한 곡의 앨범을 보여 줍니다. 앨범 정보와 표지에서 뽑은 색은 용눈이가
로그인해 있을 때 DB에 저장되고, 로그인하지 않은 방문자는 저장된 내용을 봅니다. DB가 없으면 이 기능만 꺼지고
나머지는 그대로 동작합니다.

## 주간 매거진 메일 (선택)

홈 오른쪽 STAY CONNECTED의 신청을 받아 매주 메일을 보냅니다. 공유 DB가 먼저 필요하고, 발송은 Gmail SMTP(앱 비밀번호)를 씁니다.

1. `.env.local`에 `GMAIL_USER`, `GMAIL_APP_PASSWORD`(앱 비밀번호 16자, 공백 없이), `SITE_URL`을 넣고 `npm run db:migrate`
2. 구독 신청 → 확인 메일의 링크에서 버튼을 눌러야 구독이 시작됩니다(더블 옵트인). 모든 메일에 해지 링크가 있습니다.
3. 발송은 사람이 확인한 뒤에만 합니다.
   - `npm run issue:draft` 이번 주 초안(용눈이가 가장 많이 들은 곡 최대 25곡) 만들기, 미리보기 파일 경로를 출력
   - `npm run issue:send -- --to 내주소@gmail.com` 나에게만 시험 발송 (발송 처리 안 됨)
   - `npm run issue:send` 받을 사람 목록만 확인
   - `npm run issue:send -- --confirm` 구독자 전체에게 발송하고 발송 완료로 표시

Gmail 개인 계정은 하루 500통 안팎이라 400명을 넘으면 발송하지 않습니다.

**지난 호 모음** `/issues`: 홈 오른쪽 "금요일의 앨범 편지" 카드의 제목을 누르면 열립니다. 발송 완료(`sent`)된 호만 최신순으로 보여 주고(초안은 나오지 않습니다), 가장 최근 호는 크게, 이전 호는 한 줄에 5장씩 앨범 표지 카드로 놓습니다. 카드마다 호수(`NO.`), 보낸 날, 그 주 컨셉 칩(메일이 입은 색 그대로), 앨범명·가수가 있고, 메일 발송 때 Spotify 앨범 id가 저장된 호는 누르면 `/album/[id]`로 갑니다. 로그인 없이 누구나 볼 수 있고(`GET /api/issues`), 아직 보낸 호가 없으면 안내 문구만 나옵니다. 메일을 웹페이지로 그대로 다시 보여 주는 화면은 아직 없습니다. 이 페이지의 오른쪽 칸 카드에서 `신청하기 →`를 누르면 이동하지 않고 아래 "이렇게 와요" 자리에 닉네임·이메일 양식이 열리고(`접기 ↑`로 닫음), `/subscribe`와 같은 요청을 보내므로 확인 메일의 링크를 눌러야 구독이 시작됩니다. 홈 등 다른 화면의 카드는 그대로 `/subscribe`로 이동합니다. `/subscribe`의 신청 양식 아래에도 같은 "이렇게 와요" 세 줄이 보입니다(컨셉 이름은 줄바꿈 없이 한 줄).
